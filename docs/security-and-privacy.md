# الأمان والخصوصية

## حدود الوصول

Client Worker يعرض مسارات العميل فقط. Admin Worker يطبق مصادقة Cloudflare Access قبل تقديم HTML وملفات اللوحة وAdmin API. يتحقق من توقيع RS256 عبر JWKS، والـissuer والـaudience ووقت انتهاء JWT، ثم يبحث عن البريد في قائمة أدوار الخادم. يعمل قرار الدور داخل API. طلبات الكتابة تتطلب Origin مطابقًا، ولوحة v2 تستخدم جلسة Cloudflare Access. تعرض React القيم كنص وتطبق صفحة الإدارة Content Security Policy.

## التراخيص والأجهزة

يولّد الخادم كود ترخيص من 128 بت عشوائية وتوكن جلسة من 256 بت عشوائية. تخزن D1 بصمات SHA-256. يستعمل Windows بصمة ثابتة متوافقة مع v1 مبنية من MachineGuid. رمز الجلسة في `activation.bin` محمي بـDPAPI لحساب Windows الحالي. محتوى التخزين يسمح بالتعرف على الجلسة عند التحقق المباشر. تفويض التشغيل قصير العمر وموجود في ذاكرة العملية فقط.

سجل التدقيق يحفظ البريد الإداري والإجراء والكيان والوقت والحقول اللازمة. سجل الجهاز يحتوي على بصمته وتواريخ التفعيل وآخر ظهور. مفتاح IP يمر إلى Cloudflare Rate Limiting لفترة حد الطلبات، وتستعمل الجلسة بصمة رمزها. السجلات التطبيقية تكتب نوع فشل الخدمة فقط. احصر من يستطيع عرض بيانات D1 واضبط مدة حفظ السجلات حسب سياسة التشغيل.

يفحص Client Worker حد الأجهزة في معاملة واحدة مع تسجيل المقعد. حدود الطلبات تُطبق تقريبًا لكل موقع Cloudflare. أرقام حديث النشاط تعتمد على تحديث متدرج لآخر ظهور. عند قطع الإنترنت قد يبقى التصريح الحالي ساريًا حتى موعد التحقق أو انتهاء التصريح بحد أقصى نحو 128 ثانية. إشعارات تغير الشبكة وSleep/Resume والساعة تبطل التصريح عند رصدها.

## أسرار الإصدار

احفظ مفتاح التوقيع القديم في ملفه المحمي بـDPAPI. ملف `update-keys.json` يحتوي على مفاتيح عامة فقط. أسرار GitHub Environment لا تمر إلى Pull Requests. إصدار الجسر يثق بالمفتاحين أثناء الانتقال، وتستخدم الإصدارات التالية مفتاح v2. بيان التحديث يثبت نسخة المثبّت والقناة والرابط والحجم والبصمة. Windows قد يعرض SmartScreen حسب حالة توقيع Authenticode وسياسة الجهاز.

التطبيق محلي والمصدر متاح، لذلك يستطيع شخص يعيد بناء نسخة معدلة تغيير منطق التحقق في نسخته. يدير هذا النظام صلاحيات نسخة التوزيع الرسمية الصادرة من قناة موثوقة.
